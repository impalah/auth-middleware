auth_middleware.authz.guards.require_permission(permission: str, *, scope: ScopeSource | None = None, authz: Authz | Callable[[Request], Authz] | None = None) → Callable[[...], Awaitable[AuthzContext]][source]

Build a FastAPI dependency that enforces permission in scope.

The store factory is invoked lazily, when the dependency runs; FastAPI resolves the sub-dependencies of a route in declaration order, so a dependency that binds row-level security for the request must be declared before this guard.

The guard never skips when AUTH_MIDDLEWARE_DISABLED is set: the synthetic user is rejected with 401.

Parameters:

  • permission – Permission name (a StrEnum member is accepted).

  • scope – Where the scope comes from. Defaults to the global scope.

  • authz – An Authz or a function of the request returning one; default Authz.of(request) (app.state.authz).

Returns:

A dependency returning the AuthzContext.

async authorize(principal: Principal, permission: str, scope: ScopeRef) → AuthzContext[source]

Authorize or raise.

Algorithm:

  1. catalog.spec(permission) (unknown -> UnknownPermissionError).

  2. The permission’s scope kind must equal scope.kind (else ScopeKindMismatchError).

  3. Ask every resolver; union the roles and merge attributes (later resolvers win on key clashes).

  4. No result: ScopeNotVisibleError if the scope kind hides existence, else PermissionDeniedError.

  5. Permission not in the union of the roles’ permissions -> PermissionDeniedError.

  6. Return the AuthzContext.

Raises:

  • UnknownPermissionError – Programming error.

  • ScopeKindMismatchError – Programming error.

  • ScopeNotVisibleError – Principal has no active assignment in scope.

  • PermissionDeniedError – Principal lacks the permission.

async check(principal: Principal, permission: str, scope: ScopeRef) → DecisionKind[source]

Service, cache and events

class auth_middleware.authz.service.AssignmentService(admin: AssignmentAdmin, catalog: PermissionCatalog, *, before_change: Sequence[Callable[[AssignmentChange], Awaitable[None]]] = (), after_change: Sequence[Callable[[AssignmentChange, Assignment], Awaitable[None]]] = ())[source]

Bases: object

Validated writes over an AssignmentAdmin, with application hooks.

The library ships no domain rule: an application plugs its own into before_change (raise to veto; nothing is written) and after_change (cache invalidation, audit, notifications). Example, the “last owner” rule:

async def last_owner(change: AssignmentChange) -> None:
    leaving = change.kind == "revoke" or (
        change.kind == "change_role" and change.new_role != "OWNER"
    )
    if leaving and change.old and change.old.role == "OWNER":
        owners = [
            a for a in await service.members(change.scope)
            if a.role == "OWNER" and a.status.value == "active"
        ]
        if len(owners) <= 1:
            raise LastOwnerRequiredError()

service = AssignmentService(admin, catalog, before_change=[last_owner])

Changes of one scope are serialised within this process (the veto hooks and the write run under a per-scope lock), so concurrent requests cannot both pass the same check. Several processes/instances still race (two owners revoking each other on different servers): enforce hard invariants in the store as well (a constraint or transaction of your own adapter).

A role is bound to a scope kind through its permissions: every permission of the role must belong to the kind of the scope it is assigned in.

Parameters:

  • admin – The write side of a store.

  • catalog – Used to validate roles.

  • before_change – Veto hooks, run in order before any write.

  • after_change – Hooks run in order after a successful write.

class auth_middleware.authz.cache.CachingAssignmentStore(inner: AssignmentStore, *, ttl_seconds: float, max_entries: int = 10000, clock: Callable[[], float]=<built-in function monotonic>, i_understand_stale_authorization: bool = False)[source]

Bases: object

Decorator over any AssignmentStore (and AssignmentAdmin if it is one).

get_assignment caches positive and negative results; a negative entry lives at most ttl_seconds / 4. Writes through this instance invalidate the affected key at once. list_assignments and list_for_scope are never cached. The key is (principal_id, scope.kind, scope.id).

Parameters:

  • inner – The store to wrap.

  • ttl_seconds – Entry lifetime; above 60 needs i_understand_stale_authorization=True.

  • max_entries – Oldest entries are evicted beyond this.

  • clock – Monotonic clock (injectable for tests).

  • i_understand_stale_authorization – Allow a TTL above 60 s.

Raises:

ConfigurationError – Non-positive TTL, or TTL > 60 s without the flag.

class auth_middleware.authz.stores.sql.SqlAssignmentStore(session_provider: Any, *, table_name: str = 'authz_assignment', before_query: Callable[[AsyncSession, ScopeRef | None], Awaitable[None]] | None = None, commit: bool = True)[source]

Bases: object

AssignmentStore + AssignmentAdmin over a SQL table.

Three ways to inject a session:

  1. async_sessionmaker: a short session per call (singleton store).

  2. A callable returning an async context manager yielding a session.

  3. An already open AsyncSession (per-request store built by a StoreFactory): the store never commits, rolls back or closes it, so reads and writes happen in the caller’s transaction.

Parameters:

  • session_provider – One of the three shapes above.

  • table_name – Table name (a plain SQL identifier).

  • before_query – Awaited before every statement with the session and the scope (None for the cross-scope list_assignments). This is where an application binds row-level security. Exceptions propagate.

  • commit – Commit after writes when the store owns the session. Forced off for an injected open session.
